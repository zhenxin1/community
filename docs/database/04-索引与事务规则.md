# 索引与事务规则

## 账号

用户名唯一，小写归一化；注册 INSERT 不接受 role，默认 USER。登录不再联查角色权限表。头像先上传为 TEMP，保存资料时锁定用户及媒体，验证归属、类型及有效期，然后绑定和替换旧头像。冻结、改密、角色变更递增 auth_version；管理员变更身份时锁定所有 ACTIVE ADMIN，保护最后一名有效管理员。当前仅实现用户端账号与资料，管理员身份设置接口仍待开发。

## 领养

同意申请以宠物行为锁中心，更新选定申请、其他待处理申请、宠物状态、progress 和通知，同事务提交。唯一生成列保证一个宠物只能有一位选定领养人。progress 每项为 id/status/note/createdAt/actorId，id 是稳定递增序号字符串；最多 100 项；不能漏记和修改已有项。只记录有限状态变更，达到上限返回 STATE_CONFLICT 并人工处理。

双人会话以宠物和有序参与者唯一；消息仍一条一行。发送者客户端消息 UUID 唯一，重复内容不重复落库。更新已读位置先验证消息属于本会话且位置前移，按 low/high 参与者更新对应列。预约按参与者 ID 固定顺序加锁并验证时间不重叠。

## 社区

POST、DIARY、HELP 共用内容表；PRIVATE 仅日记允许，只能作者读取。tags 是最多 5 个去重、1–20 字字符串的 JSON 数组；DB CHECK 保证数组和数量，Service 验证每项。分类、评论、点赞仍使用各自的关系表。评论归属和举报目标权限由 Service 校验，不因表合并放宽。

## 站内消息

管理员群发先写 is_broadcast=1 的主记录，无收件人；再为每个实际收件人写 is_broadcast=0 的消息，broadcast_id 指回主记录，最后设置 recipient_count，均在同一事务完成。用户查询始终限定 recipient_id=当前用户 AND is_broadcast=0。主记录 target_type、created_by 必填；普通消息不填写。Service 验证 broadcast_id 不指向其他消息子行。唯一索引阻止同一次公告给同一人重复发送。

## 商城

模拟购买直接成功：服务端读取并验证商品、价格、购物车和地址，锁商品并检查库存，创建订单／快照明细、扣库存、清购物车、保存通知及幂等结果，同事务提交。购物车和详情报价不是可信价格。没有支付宝、微信或真实支付回调。

取消／退款锁订单，检查状态，只允许整单；取消订单回补库存；退款仅 restock=true 且管理员确认收货后回补。库存操作、最终状态及全额退款金额和时间同事务。shop_refund 保存申请审核；订单保存结果。重复处理不得重复加库存。取消已模拟购买的订单也属于模拟全额退款。商品库存人工调整写 operation_log；不另建流水表。订单状态及 paid_at/shipped_at/completed_at/cancelled_at/refunded_at 支撑进度展示。

## 通用

保留 api_idempotency，24 小时内同用户同方法同路径同 UUID 同请求重放成功响应，冲突拒绝；业务事务成功时同步写成功结果，失败回滚。临时密码响应必须加密保存，密钥不落数据库。operation_log 只追加不改删。分页索引见数据字典，以范围、状态及 created_at/id 稳定排序。
