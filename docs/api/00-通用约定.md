# 00 通用约定

[返回总目录](README.md)｜[数据模型](06-数据模型.md)｜[状态和权限规则](07-状态流转与业务规则.md)

## 1 地址、编码与数据类型

- 本地默认地址：`http://127.0.0.1:18080`。当前只实现账号与资料接口，其余接口按设计逐步开发。
- 前缀：`/api/v1`；JSON 字段小驼峰；编码 UTF-8。
- JSON 写请求：`Content-Type: application/json`；文件使用 `multipart/form-data`，浏览器自行设置 boundary。
- 所有 ID 为十进制**字符串**，如 `"1001"`，避免 JavaScript 大整数精度丢失。
- 所有金额用整数**分**，如 `2990` 表示 29.90 元；不传浮点价格。金额由后端核算。
- 时间为 RFC3339，例 `2026-11-11T10:00:00+08:00`，日期展示按 Asia/Shanghai。
- 请求体仅允许列出的字段；未明确标注可选的字段均必填。PUT 完整提交可编辑字段；可清空文本传 `""`，可清空列表传 `[]`；不使用隐含 null。布尔值是 true/false，不能传字符串。
- 所有用户填写内容为纯文本，前端转义展示；链接只接受 HTTP/HTTPS，不接受脚本 URL；服务端不抓取用户链接。

## 2 登录与 Cookie

采用服务端 Session，Cookie 名 `JSESSIONID`，HttpOnly、SameSite=Lax、Path=/api。正式 HTTPS 部署设置 Secure。空闲 8 小时过期；活跃合法请求续期。退出只撤销当前会话，修改或重置密码、冻结用户撤销该用户全部会话。

调用顺序：

1. `GET /api/v1/common/session`，浏览器保存 Cookie，前端保存返回的 csrfToken。
2. `POST /api/v1/user/auth/login` 或 `/user/auth/register`；携带 Cookie 与 `X-CSRF-Token`，成功后用新的 csrfToken 替换旧值。
3. 后续请求让浏览器携带 Cookie；POST、PUT、DELETE 等全部写请求还须 `X-CSRF-Token`。
4. 刷新页面后再调 common/session 获取当前会话的令牌，然后 GET auth/me 判断登录状态。Session 接口自身不会暴露其他人的身份。

不把 Cookie 手动写进 localStorage，不把用户 ID 当登录凭据。默认开发代理及同源部署，不开放任意跨域带凭据访问。需要分域时须另行明确受信任域名、Cookie 与 CORS 配置。

| 文档权限 | 含义 |
| --- | --- |
| PUBLIC | 匿名可访问；注册和登录仍必须先初始化匿名 Session 并带 CSRF |
| OPTIONAL | 可匿名浏览公开信息；有效会话才返回当前用户点赞等状态；无效会话按匿名处理，不放开私密访问 |
| USER | 登录且 ACTIVE；只能操作本人或业务规则允许的资源 |
| ADMIN | 登录且 ACTIVE，当前用户 role=ADMIN；仍检查资源隐私与业务状态 |



管理员重置后，`mustChangePassword=true` 的会话只允许 common/session、user/auth/me、admin/auth/me、user/password、用户或管理端退出；其他受保护操作均返回 PASSWORD_CHANGE_REQUIRED。

## 3 统一成功与失败返回

成功为 HTTP 200，code 固定 `OK`。无业务数据也返回 ActionResult，不使用空 body 或 204。

```json
{"code":"OK","message":"成功","data":{"success":true},"requestId":"req_20261111_001"}
```

失败使用对应 HTTP 状态，不能一律返回 200；message 可供显示，业务判断看 code。fieldErrors 只有参数校验失败时非空。

```json
{"code":"VALIDATION_ERROR","message":"请检查输入参数","requestId":"req_20261111_001","fieldErrors":[{"field":"items[0].quantity","message":"必须介于 1 和 99 之间"}]}
```

不返回异常堆栈、SQL、密码或服务器路径。所有响应使用 requestId 供排查；令牌和临时密码等敏感响应使用 `Cache-Control: no-store`。

## 4 分页、搜索和排序

所有列表均使用 page（默认 1）和 pageSize（默认 20，范围 1–100）。超过末页返回 records=[]；total 是相同过滤条件下的总数，所有分页结构相同：

```json
{"code":"OK","message":"成功","data":{"records":[],"total":0,"page":1,"pageSize":20},"requestId":"req_20261111_001"}
```

query 参数省略表示不筛选；keyword 去首尾空白，按接口说明做包含匹配。不得将用户输入直接拼接 SQL。创建时间区间是 `[createdFrom, createdTo)`，两端均可单独提供；同时提供时下界须早于上界。列表默认 createdAt 降序、ID 降序；无 createdAt 的列表默认 ID 降序。各接口明确的分类排序、消息排序及匹配分数排序优先。

## 5 并发版本与重试

存在 version 的可编辑资源，每次有效更新后 version+1。更新、状态变更以及删除均传最近读取到的版本；地址新增等创建接口无版本。冲突返回 409 VERSION_CONFLICT，前端重新读取后让用户确认，不能覆盖别人的更新。

部分幂等集合操作（点赞、取消点赞、收藏、已读、购物车绝对数量）不要求版本：重复设置同一值保持相同结果。DELETE 删除普通内容后再次访问返回 404，取消收藏和移除购物车等专门声明幂等的操作除外。

标明 Idempotency-Key 的接口必须传 UUID。作用域为当前用户 + HTTP 方法 + 路径，保存请求规范化摘要和结果 24 小时。相同键同请求重试返回原结果；相同键不同请求或原请求仍执行中返回 409 IDEMPOTENCY_CONFLICT。幂等检查先于版本检查，成功响应重放不得再次修改库存。异常回滚后允许原键重试，不能把失败事务永久当成已完成。

原请求仍执行时客户端稍后以相同键重试；已成功而响应丢失时也是原键。用户明确发起新操作才使用新键。24 小时后缓存可能过期，因此有效申请唯一约束、状态校验和库存锁仍必须存在。

## 6 媒体文件与访问

先上传文件，拿到 Media.id，再传给业务资源 mediaIds。每个文件单独上传；最多 9 个绑定文件，按 mediaIds 顺序展示。常规图片 JPEG/PNG/WebP/GIF ≤5 MiB（5×1024×1024 字节），视频 MP4/WebM ≤20 MiB；单请求只允许一个文件，multipart 总体上限可设置 21 MiB。头像和商品只允许图片。服务端同时检查扩展名、MIME 和实际文件特征，避免只相信客户端 Content-Type。

businessType 对应 AVATAR / PET / POST / DIARY / HELP / PRODUCT；用户上传接口禁止 PRODUCT，商品图片走管理端接口。用途必须与绑定资源匹配。临时媒体仅上传者可读，24 小时未绑定清理；一个媒体 ID 仅能绑定一个业务对象，保留原有同资源绑定不算重复绑定。

媒体统一通过 `/api/v1/media/{mediaId}/content` 读取，不对客户端暴露磁盘绝对路径。PUBLIC+PUBLISHED 资源媒体和有效头像可匿名读；未上架商品图片仅 ADMIN，公开商品需上架且分类启用。宠物审核媒体可 ADMIN 访问；PUBLIC 社区审核媒体可 ADMIN 访问。**PRIVATE 日记无论管理员角色如何都仅作者可读**。作者可读本人非删除资源及绑定媒体。业务内容删除后媒体立即不可读，后台延迟清理不能延迟权限失效。

完整读取返回 200 文件字节，合法单一 Range 返回 206，并带 Accept-Ranges、Content-Range；无效范围返回 416 JSON 错误。每次读取重新鉴权，设置 `Cache-Control: private, no-store` 和 `X-Content-Type-Options: nosniff`。无权读取统一 404。图片视频原始文件上传不承诺转码、缩略图或内容识别服务。

## 7 错误码

每个接口列出主要错误码，其他公共校验与传输错误仍按本表。响应结构见 Error 模型。

| HTTP | code | 含义 | 前端处理 |
| --- | --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 字段缺失、类型错误、未知字段、枚举或跨字段约束不满足 | 按 fieldErrors 修正后再提交 |
| 400 | `MISSING_IDEMPOTENCY_KEY` | 需要防重复的请求未携带幂等键 | 生成 UUID，同一操作重试复用 |
| 401 | `UNAUTHENTICATED` | 未登录、会话失效或已退出 | 跳转登录；不自动重复购买 |
| 401 | `INVALID_CREDENTIALS` | 账号或密码错误 | 统一提示账号或密码错误 |
| 403 | `FORBIDDEN` | 缺少管理员身份或不允许该操作 | 隐藏操作入口，保留服务端校验 |
| 403 | `CSRF_INVALID` | 写请求令牌缺失或失效 | 重新获取会话及令牌后由用户重试 |
| 403 | `ACCOUNT_FROZEN` | 账号被冻结 | 提示联系管理员 |
| 403 | `PASSWORD_CHANGE_REQUIRED` | 管理员重置后尚未修改临时密码 | 进入修改密码页面 |
| 404 | `RESOURCE_NOT_FOUND` | 资源不存在、已删除或不属于当前用户 | 提示资源不可访问；不泄漏资源是否存在 |
| 409 | `USERNAME_EXISTS` | 账号已被注册 | 更换账号 |
| 409 | `NAME_EXISTS` | 角色或同域分类名称重复 | 更换名称 |
| 409 | `VERSION_CONFLICT` | 传入 version 已过期 | 重新读取资源，由用户确认修改 |
| 409 | `STATE_CONFLICT` | 当前状态不支持此操作 | 刷新状态，不盲目重试 |
| 409 | `DUPLICATE_APPLICATION` | 已存在有效领养申请 | 打开已有申请 |
| 409 | `DUPLICATE_CASE` | 同一对象已有待处理举报或投诉 | 打开待处理记录 |
| 409 | `APPOINTMENT_CONFLICT` | 预约参与人时间重叠 | 另选时间 |
| 409 | `PRICE_CHANGED` | 实时总额与用户确认金额不一致 | 重新试算，请用户确认新金额 |
| 409 | `INSUFFICIENT_STOCK` | 当前库存不足 | 调整数量或移除商品 |

| 409 | `MEDIA_IN_USE` | 文件已被资源绑定 | 修改业务资源解除绑定后再处理 |
| 409 | `RESOURCE_IN_USE` | 分类或角色仍被引用 | 先解除引用或改为停用 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同一幂等键对应不同内容或同键请求正在处理 | 不换键重复扣库存；完成后使用原键查询重试 |
| 409 | `LIMIT_EXCEEDED` | 有效需求或地址数量超过限制 | 关闭或删除旧记录 |
| 413 | `FILE_TOO_LARGE` | 单文件或请求体超过大小限制 | 压缩或缩短后重传 |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | 请求类型或上传文件实际格式不支持 | 使用文档规定的类型 |
| 416 | `RANGE_NOT_SATISFIABLE` | 媒体读取字节范围无效 | 按文件总长度修正 Range |
| 429 | `TOO_MANY_REQUESTS` | 登录失败或提交频率触发限流 | 按 Retry-After 秒数等待 |
| 500 | `INTERNAL_ERROR` | 未预期的服务端异常，写事务回滚 | 展示 requestId，幂等操作使用原键重试 |


## 固定身份

User.role 只有 USER、ADMIN。普通注册固定为 USER；管理员接口只允许 ACTIVE+ADMIN，会话每次校验当前身份。角色变更递增 auth_version；保护最后一名 ACTIVE 管理员。取消自定义角色及按权限项授权。
