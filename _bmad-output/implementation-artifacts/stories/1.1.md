# Story 1.1 注册登录并退出

状态：review。技术证据已归档，最终人工验收待记录。

## 用户故事
作为成员，我希望安全进入本人功能并可退出当前会话，以便在当前业务阶段得到明确且可验证的处理结果。

## 关联与前置
- 功能需求：FR-01 FR-02。
- 页面入口：`/login`。
- 前置故事或条件：无业务前置；运行环境与账号表可用。
- 详细业务规则：[PRD](../../planning-artifacts/PRD.md)；技术约束：[架构](../../planning-artifacts/architecture.md)。

## 输入与主流程
本故事接收账号、密码、确认密码。界面先展示可操作信息与当前状态，提交期间提供处理反馈。Controller只处理请求合同，Service核对身份、对象关系、字段与业务状态，Mapper在统一数据库完成必要读写；页面按实际响应展示结果，不自行伪造成功状态。

## 验收标准

### AC-1.1-01
给定上述参与者和相应业务数据，当通过页面或直接请求执行该场景，则：给定合法注册字段，提交后创建唯一ACTIVE/USER，昵称初始为规范化账号，转到登录页，不自动发会话。

### AC-1.1-02
给定上述参与者和相应业务数据，当通过页面或直接请求执行该场景，则：给定相同规范化账号，重复注册不能新增第二个账号；附加role/status字段返回400。

### AC-1.1-03
给定上述参与者和相应业务数据，当通过页面或直接请求执行该场景，则：给定ACTIVE账号，仅正确密码可获得会话；错误账号或密码返回通用认证失败，密码不回显。

### AC-1.1-04
给定上述参与者和相应业务数据，当通过页面或直接请求执行该场景，则：给定当前会话退出，后续受保护请求拒绝；另一个设备的会话不因退出当前会话撤销。

## 实现与测试任务
1. 页面：展示本故事所需数据、操作与加载/空/错误状态，保护非敏感输入；密码字段不作为重试缓存。
2. Controller：保持统一请求字段及错误语义，拒绝未知或不合法输入，不接受客户端伪造身份。
3. Service与Mapper：复用身份能力，校验归属和状态；相关写入按既定事务及锁序执行。
4. 正向验证：从页面或HTTP完成主流程，核对响应与数据库最终结果。
5. 负向与重复验证：覆盖游客、普通账号越权、非法字段、过期版本或重复操作中与本故事相关的情况。
6. 证据与评审：关联已有自动化结果和页面记录，记录修正；人工接受后再按实际决定更新冲刺状态。

## 验证入口与完成定义
自动化入口为`tests/integration.py`、`tests/quality.py`及后端JUnit。测试名称、实现领域与FR的具体对应见`docs/traceability.md`，实际结果见`evidence/verification.md`。浏览器记录仅代表已执行的页面路径，不替代未执行的场景。
完成应具备可运行页面与接口、权限和异常处理、可核对测试、文档一致及负责人接受；缺少人工接受时保留review，不以技术通过自动变为done。
