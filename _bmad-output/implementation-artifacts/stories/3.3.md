# Story 3.3 选择地址并核对优惠

实施状态：`review`。状态与`sprint-status.yaml`一致，技术验证和人工接受分别记录。

## 用户故事

作为消费者，我希望选择收货信息并核对实际优惠，以便确认收货信息及实际应付金额。

## 关联与前置

- 功能需求：FR-16 FR-17。
- 页面入口：`/checkout`。
- 前置故事或条件：1.1、3.2。
- 详细业务规则：[PRD](../../planning-artifacts/PRD.md)；技术约束：[架构](../../planning-artifacts/architecture.md)。

## 输入与主流程

消费者维护本人地址并请求所选商品的服务端报价。系统按最高档满减后八折计算整数分金额，报价绑定地址和商品版本。

## 验收标准

### AC-3.3-01

本人新增编辑地址，使用他人地址拒绝；旧版本编辑不能覆盖新版本。

### AC-3.3-02

只按选中商品计算总价，300/600/1500元门槛分别应用最高档满减后八折。

### AC-3.3-03

所选300元与未选600元组合仍应付216元；舍入与整数分函数一致。

### AC-3.3-04

更改商品或地址后必须核对最新报价，订单保存独立快照而非可变地址引用。
