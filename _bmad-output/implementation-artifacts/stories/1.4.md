# Story 1.4 管理员查询与处置用户

文档状态：`Done`。

实施状态：`done`。状态与`sprint-status.yaml`一致，技术验证和人工接受分别记录。

## 用户故事

作为平台管理员，我希望准确定位普通账号并作出可解释处置，以便准确定位账号并追溯管理处理结果。

## 关联与前置

- 功能需求：FR-04 FR-05。
- 页面入口：`/admin`。
- 前置故事或条件：1.1、1.3。
- 详细业务规则：[PRD](../../planning-artifacts/PRD.md)；技术约束：[架构](../../planning-artifacts/architecture.md)。

## 输入与主流程

管理员查询普通账号及状态，选择对象并填写处置原因和操作标识。服务端核验版本，事务内更新状态、说明通知和命令结果。

## 验收标准

### AC-1.4-01

ADMIN可按账号和状态分页查询；USER或游客直接访问后台接口拒绝。

### AC-1.4-02

冻结普通账号后状态、原因、版本和说明通知共同保存，旧会话失效。

### AC-1.4-03

同一命令同载荷重试返回原结果，不新增第二条处置通知；异载荷复用返回冲突。

### AC-1.4-04

解冻必须基于当前版本；完成后旧会话仍失效，管理员自身及其他ADMIN不能作为处置目标。
